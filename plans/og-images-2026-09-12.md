# OG images — regenerated in the new brand (2026-09-12)

~1,670 of 1,789 monthly clicks were landing on pages whose share card was still the old cream/orange
brand. Every page card is now the field-green Repro Shop card (Paper board `BIM-0`).

## What was generated

`scripts/og-v2.py` is still the only generator. It gained three things rather than a sibling script:

- `tool:<slug>` — reads `src/lib/pseo/tool-cards.js` through node, so a new registry entry gets a card
  with no edit here. Eyebrow `FREE TOOL · <meta>`, headline the registry title, sub the registry `desc`.
- `alt:<slug>` — reads `src/lib/pseo/comparisons.js` the same way (competitor, headline, metaDescription).
- `fmt:<png|jpg|webp>` — the html-to-[format] pages are separate ranking URLs sharing one registry
  entry, so each gets its own card rather than a shared one headlined "HTML to image".
- `--list tool|alt` prints the slugs, which is what the render loop iterates.

Rasterised at 1200×630 with headless Chrome, one file each:

## Headlines

The cards use the registry titles, not the routes' `<h1>`s. The dedicated routes' H1s are the same
words in caps ("CSV TO PDF"), but the nine use-case routes read "Generate Badge Generator",
"Generate Membership Card Generator", "Generate Email Header Generator" — a duplicated word that
should be fixed on the pages, not reprinted on a share card. `HEADLINES` in the script is the
per-slug override if a card should ever differ.

## Routes

Every hardcoded `media.pictify.io/<hash>.png` page card is now a `https://pictify.io/og/...` path, and
`twitter:image` equals `og:image` everywhere. Files touched: html-to-[format] (per format),
url-to-image-generator, og-image-generator + [platform] (including the `screenshot` ImageObject in its
structured data), code-to-image, csv-to-pdf, certificate-generator, online-invoice-generator,
[usecase] (falls back to `/og/tools/<useCaseId>.png`), integrations/[slug] (uses the integrations

Left alone deliberately, both sample images rather than page cards: `src/routes/dev/tool-states`

## Blog posts — done 2026-09-12

All 20 published posts now carry a new-brand card as `heroImage` (a URL string on the `post` type),
hosted on the Sanity CDN (`cdn.sanity.io/images/ayq6mmxw/production/<hash>-1200x630.png`), uploaded
with `npx @sanity/cli assets upload` and set via patch + publish. Cards were rendered with
`python3 scripts/og-v2.py card:<json>` — the new `card:` mode takes `{eyebrow, headline, sub, path,
hsize, hline}` for content that lives outside the repo. Eyebrow = "Pictify blog · <Month YYYY>",
headline = post title (58/48/42 px by length), sub = post description; the URL line drops to
`pictify.io/blogs` when the path is longer than 72 characters (four posts).

For a new post: fetch title/description/date from Sanity, write the JSON, render, upload, set
`heroImage`. The on-page hero plate shows the same card (1200×630 fits the 420 px plate exactly).

## Blog plates — replaced the title cards, 2026-09-12 (later the same day)

The user rejected the title cards as post heroes: the title is already set as text on
the post page and on the /blogs card, so a title on the art said it three times. Refero
references (GitHub ReadMe, Figma Shortcut, Raycast) all keep post covers text-free and
let the page carry the title.

`scripts/blog-plate.py <slug>` now renders a **text-free 1200×630 plate**: the site's own
band vocabulary with the words removed — resolving pixel cluster cut by the right edge,
a flat sheet (ink border, hard offset shadow, printed bars) on the left, a tilted capsule
off an edge, a sparse baseline run flush with the bottom. Ground rotates per post among
powder / rose / sky / paper / canvas (never field: the band above is field). Everything
is seeded from the slug, so a re-render is byte-stable; `--ground <name>` overrides when
the shelf order stacks one colour (quote-image-generator is forced to sky).

One asset per post serves the hero plate, the /blogs card and og:image (`shareImage`
falls back to `heroImage` in the route), so no Sanity schema change. Upload with
`npx @sanity/cli assets upload`, set `heroImage`, publish. The 20 title-card assets from
the morning are orphans in the dataset; harmless, delete if tidying.

## Blog covers — contextual specimens, 2026-09-12 (third pass, approved)

The abstract plates were rejected too ("just placeholder and not contextual"). What the
references actually do (GitHub ReadMe, Figma Shortcut, Raycast) is show the article's
subject on the cover. For Pictify that means: **the cover is a rendered specimen of the
thing the post teaches you to make.** `scripts/blog-cover.py <slug>` holds one scene per
post (SCENES): a browser becoming a PNG file, a certificate with three sheets fanned
behind it, a GIF filmstrip, a Handlebars template beside its render, a ranked list,
comparison grids, a CSV fanning into cards, a tweet card, a 1080 quote card, a course
card, a 16:9 thumbnail with its Node script, an email with a per-recipient banner, a
dashboard snapshot with its Python, a wall of UGC posts, three image weights, three
viewports, a 5×2 contact sheet of use cases.

Rules: never the post title; specimen text is allowed (it is the specimen's content); built
from the site's own parts (sheets with 1.5px ink border + 8px offset shadow, mono labels,
riso palette), the pixel cluster shrunk to a corner signature; a mono chip bottom-left
names the transformation ("URL → PNG"). Fonts load from Google Fonts at render time, so
the rasteriser needs network; wait for networkidle before the screenshot.

For a new post: add a scene function to SCENES, render, upload with
`npx @sanity/cli assets upload`, set `heroImage`, publish. `blog-plate.py` (abstract
plates) is superseded and can be deleted.
